# yoyoko 内存与界面资源调度

2026-09-21：Phase 1 的局部优化，不表示整机闲置内存或聊天负载已达标。

## 已实现

`UI/Resources/VisualResourcePolicy` 集中定义档位；`WindowResourceGovernor` 适配窗口、输入与低频采样，Shell 把预算交给图片所有者。没有新增业务模块依赖、协议字段或全局账号状态。

| 状态 | 附件预览像素预算 | 头像像素预算 | 每类图片下载并发 | 装饰媒体 |
| --- | --- | --- | --- | --- |
| 前台交互 | 16 MiB | 8 MiB | 4 | 可播放 |
| 失焦，或 60 秒无键盘/指针操作 | 4 MiB | 1 MiB | 1 | 头像静态，壁纸暂停 |
| 内存压力保护 | 2 MiB | 1 MiB | 1 | 头像静态，壁纸暂停 |
| 隐藏 / 最小化 | 0 | 0 | 0 | 清空图片引用、释放壁纸播放器与帧 |

预算是解码后的像素量，不是进程 RSS 上限；下载缓冲、解码器临时内存、Avalonia/Skia 渲染缓存与运行时需要单独计算。并发从 4 降到 1 时让正在进行的请求收尾；隐藏时取消可重建的图片请求。附件和头像各自拥有有限并发，因此前台最多同时有 8 个图片请求。

- 附件预览按当前消息行建立所有权，同链接复用；消息被移出时间线、切频道或退出时清空引用并 Dispose。宽高均不超过 128 px，单次下载不超过 512 KiB。
- 缩减预算时，被消息引用的图片也会移除；超限附件保留可下载的文件项。没有为每一行或每次刷新创建等待任务。
- 头像只保留当前时间线和自己的账号所需资源；同用户/链接请求去重，失败不循环重试。动画最多 48 帧，剩余预算不足则使用首帧。低资源档位使用静态缩略图；头像变更、实例切换或驻留档位变化后重新评估。
- 隐藏时暂停 UI 消息投影更新，保留 Core 时间线及 Gateway → SQLite 同步；恢复时同步当前快照，以有限并发加载当前图片。发送、文件操作和语音会话不会被资源调度器停止。
- 壁纸保留独立的窗口暂停、资源降载、用户减少动效条件；任一条件要求暂停就不播放。隐藏会使未完成解码的交付失效，但同步解码本身不能中途取消。

## 压力判断与恢复

可见窗口每 15 秒采样一次进程 WorkingSet/RSS，以及 .NET 最近一次 GC 的系统内存负载快照。进程 RSS ≥ 256 MiB 或快照负载 ≥ 90% 时进入保护档；低于 224 MiB 且负载低于 80% 持续 30 秒才恢复，避免来回震荡。隐藏时停止周期采样，窗口事件立即应用隐藏预算。

这些阈值是初始保护策略，不是平台内存压力通知。GC 快照可能过期；不为刷新它强制 GC，不调用操作系统 working-set trim，也不把 RSS、GC heap 和 native 分配混为一谈。跨平台系统压力通知仍未接入。

## 从 ECHO UltraLight 借鉴的范围

参考了 ECHO 的 `WindowResidencyController`、`mainWindowTrayLoadShedding`、`UltraLightModeService` 与窗口驻留说明：可见性驱动降载、释放可重建资源、用取消和代次检查拒绝过期恢复、保留核心业务状态。

没有复制 Electron Renderer 销毁、GPU runtime 重启、曲库 worker 或音乐播放逻辑。yoyoko 的 Avalonia UI 与业务当前在同一进程；基础四档保留 UI 树；可选的深度开关见下节。不承诺达到 ECHO UltraLight 的驻留内存水平。

## 可选深度 UltraLight

「设置 → 常规 → UltraLight」默认关闭，保存到客户端偏好的 `ultra_light_enabled`。打开开关后，窗口仍可正常使用；最小化或隐藏才进入深度模式。失焦、空闲和系统压力只应用基础四档，不会卸载可见页面。

- 将主要界面抽成 `ShellSurface`，由 `UltraLightWindowContent` 释放和重建 `Window.Content`；保留原生窗口外壳作为系统任务栏/程序坞的恢复入口。没有新增托盘功能，也不改变关闭窗口或退出应用的语义。
- 先停止图片工作，再卸载页面、关闭临时弹出菜单、解绑视图事件，清理 Messages / VisibleMessages / Participants 的 UI 投影。Shell、Core 时间线、账号会话、Gateway、SQLite、发送/上传、VoiceRuntime 和媒体 worker 的生命周期不变。
- 保留当前频道、草稿、待发送附件流、设置状态；恢复时重建当前消息投影，重新加载受预算限制的图片，并尝试恢复频道滚动偏移。如果后台时间线已经淘汰旧消息，不保证历史阅读位置逐像素不变。
- 暂停设置页的连接探测轮询、取消快捷键录制；不会调用语音 Leave、Connect、设备切换或修改 mute/deafen。关闭开关时若窗口仍隐藏，延迟到显示时重建，避免创建不可见页面。
- 壁纸视图在脱离视觉树时解绑长期存活的 WallpaperSession，防止旧页面被事件订阅保留。
- 页面卸载后可由 GC 回收；产品不主动强制 GC、不重启进程、不声称所有字体/主题/渲染器原生缓存立即退回系统。

聚焦入口：`dotnet run --project tests/ultralight -c Release`。测试使用真正的 App/ShellSurface 与离屏窗口，验证默认关闭、持久化、卸载后弱引用回收、重建、隐藏时关闭开关、草稿/附件流保留。语音使用真正的 VoiceRuntime 和记录调用次数的 API/媒体端口：加入后经历隐藏/恢复，Connect=1、Leave=0，频道和 mute/deafen 不变。测试内的强制 GC 仅用于证明视图可回收，产品无此调用。

开关已完成离屏渲染和 macOS 原生窗口检查：独立空缓存、回环拒绝连接的 Release 开发 host（PID 4095）中，开关 on/off 的辅助功能状态准确；启用后触发最小化，工具再次读取唤回窗口时原页面元素被新树替换且保留设置页，关闭后相同行为保留原页面树。记录为原生卸载/恢复 smoke，不把工具的自动唤回延迟当成恢复耗时。进程日志无错误。
